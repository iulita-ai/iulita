# Обзор релизов

Здесь собраны изменения релизов v0.38.0–v0.49.3. Полный changelog находится по ссылке на релиз. Наличие функции
в исходниках не означает её наличия в ранее выпущенном образе или бинарном файле.

## v0.49.3: явные запросы данных телефона

[v0.49.3](https://github.com/iulita-ai/iulita/releases/tag/v0.49.3) обрабатывает
`/phone status`, `/phone location` и `/phone notifications` как фиксированные
запросы к выбранному телефону. Они используют обычный turn, журнал и проверки
прав, согласия и native session, но не требуют решения модели о вызове tool.
Подтверждение создания формируется из настоящего результата tool; сырые данные
открываются отдельно. Неопределённые операции по-прежнему не повторяются.

## v0.49.2: соответствие OAuth-ответов контракту

[v0.49.2](https://github.com/iulita-ai/iulita/releases/tag/v0.49.2) приводит
`token_type` browser/refresh-ответов Fosite к значению `Bearer`, указанному
в опубликованной OpenAPI-схеме. Device Flow и service-ответы уже использовали
этот формат. Права, сроки токенов, ротация и отзыв доступа не меняются.

## v0.49.1: обновления чатов и browser OAuth

[v0.49.1](https://github.com/iulita-ai/iulita/releases/tag/v0.49.1) исправляет
исчерпание кэша snapshot при обновлении мобильных чатов. Предел остаётся
32 снимка на владельца: новый снимок заменяет самый старый, а его курсор
требует resync. Другие владельцы и сохранённые сообщения не затрагиваются.

Страницы входа и согласия используют `Referrer-Policy: same-origin`, чтобы
браузер сохранял Origin для POST формы. Точная проверка Origin и CSRF остаётся;
ответы с OAuth redirect сохраняют `no-referrer`.

## v0.49.0: явная цель телефона и серверное время

[v0.49.0](https://github.com/iulita-ai/iulita/releases/tag/v0.49.0) добавляет
`SendMessage.target_device_id`: выбранный телефон сохраняется вместе с принятым
turn и проверяется независимо от аргументов модели. Повтор message ID с другой
целью отклоняется. Без поля цели фиксируется исходное устройство отправителя;
неявно выбрать другой телефон владельца нельзя.

Отдельный OAuth listener выдаёт привязанные к nonce ответы `/oauth2/time`.
Идентификатор часов общий для gRPC ServerInfo, команд, lease и native session.
Перезапуск runtime или обнаруженный скачок системного времени меняет ID и
закрывает сессии со старой привязкой. Клиент по-прежнему учитывает RTT,
разрешение, погрешность, дрейф и возраст измерения.

Account security reservations теперь проходят через очередь перед SQLite writer.
Отменённый ожидающий запрос не входит в бизнес-операцию; транзакционные проверки
аккаунта и отзыва токенов сохранены.

Mobile defaults остаются выключенными, UI/Vision требуют совместной native
приёмки. Релиз backend не содержит Android-приложения и сам не включает доступ
к телефону. См. [руководство интеграции](mobile-api.md).

## v0.48.1: управление HTTP-согласиями

[v0.48.1](https://github.com/iulita-ai/iulita/releases/tag/v0.48.1) подключает
хранилище standing-согласий к production-дашборду. Авторизованный API
`/api/http-standing-grants` возвращает список и отзывает согласия вместо
перехода к HTML-приложению. Пользователь управляет только своими разрешениями;
администратор может просматривать и отзывать разрешения другого владельца.

## v0.48.0: мобильный API и удалённые клиенты

В [v0.48.0](https://github.com/iulita-ai/iulita/releases/tag/v0.48.0) добавлены отдельные OAuth2 и gRPC, несколько чатов одного владельца, задачи
телефона, приватная обработка моделью с явным согласием и ограниченные UI lease.
CLI использует Device Flow. Серверные интеграции имеют отдельную регистрацию
и Client Credentials только для чатов. Есть отключение клиентов, ротация
секретов и отзыв доступа. Все флаги по умолчанию выключены.

Перед включением прочитайте [руководство API и оператора](mobile-api.md).
Готового мобильного приложения и удалённого CLI пока нет. Симуляторы не
подтверждают работу на Android/GrapheneOS или iOS.

## v0.46–v0.47: HTTP-запросы и согласия

В [`v0.46.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.46.0) появился
`http_request`: структурированные запросы, ссылки на credentials, ограниченные
цепочки и скачивания через обязательный настроенный proxy. Прямого fallback
нет. [`v0.46.1`](https://github.com/iulita-ai/iulita/releases/tag/v0.46.1)
подключил подтверждения каналов через manager.

[`v0.47.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.47.0) добавил
длительные разрешения на мутации: точный origin на 30 дней или все origins
на 7 дней. Отзыв — через `/api/http-standing-grants`. Скачивание свыше
100 MB всегда требует нового подтверждения. Разрешение на передачу credential
конкретному origin выдаётся отдельно. См. [Навыки](skills.md) и
[Конфигурацию](configuration.md).

## v0.44–v0.45: голосовой ввод

[`v0.44.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.44.0) добавил
Whisper-совместимую транскрипцию, свой endpoint и ограничение входа 24 MB.
v0.44.1–v0.44.4 добавили настройки в дашборде, горячую перезагрузку и
использование подключения Z.ai для GLM-ASR. Если provider и ключ транскрипции
явно не заданы, доступное подключение Z.ai используется автоматически.

[`v0.45.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.45.0) включил
ffmpeg в образ. Активная обёртка преобразует форматы кроме MP3/WAV в mono MP3
16 kHz. Без ffmpeg и при ошибке конвертации отправляются исходные байты;
строгий endpoint всё ещё может их отклонить. Документированный лимит
`glm-asr-2512` — 30 секунд; автоматического разбиения длинных записей нет.
См. [голосовой ввод](channels.md#voice-input).

## v0.40–v0.43: Telegram

- [`v0.40.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.40.0): входящие
  координаты и карточки мест; отправка карточки требует явного подтверждения.
- [`v0.40.2`](https://github.com/iulita-ai/iulita/releases/tag/v0.40.2)–v0.40.4:
  HTML-форматирование, вложенные стили, цитаты, spoilers и таблицы с учётом
  отображаемой ширины emoji.
- [`v0.41.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.41.0): реакции
  обработки, закладки реакцией, копирование и удаление сообщений через `/clear`
  с учётом ограничений Telegram.
- [`v0.42.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.42.0): переход
  на `go-telegram/bot`, нативные Todoist checklists. Это одностороннее зеркало:
  отметка в Telegram не завершает задачу в Todoist.
- [`v0.43.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.43.0): ephemeral
  доставка ответов с обнаруженными секретами и `telegram.draft_streaming`.
  Draft streaming по умолчанию выключен и имеет fallback к редактированию.
  При ошибке ephemeral API возможна обычная отправка, поэтому этот режим
  не является гарантией приватной доставки.

Актуальное поведение описано в [Каналах](channels.md).

## v0.39: профили моделей и браузерные сессии

[`v0.39.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.39.0) добавил
DeepSeek/GLM, зашифрованные подключения, роли задач, явные probes, отзыв ключей
и учёт отдельных попыток. v0.39.1–v0.39.2 защитили браузерные WebSocket и
привязали WebChat к проверенному аккаунту.
[`v0.39.3`](https://github.com/iulita-ai/iulita/releases/tag/v0.39.3) добавил
платный классификатор с проверкой качества и проверенные резервные профили.

Новые подключения и назначения ролей требуют проверки и явной активации.
Probes и оценка классификатора могут тарифицироваться провайдером. См.
[профили и маршрутизацию](../model-routing.md), подробное руководство на английском.

Перед обновлением с v0.38 и старее сохраните согласованную копию SQLite и ключ
шифрования конфигурации. Индекс usage включает identity провайдера; для отката
нужна соответствующая старая база, одной замены бинарного файла недостаточно.

## v0.38: Slack

[`v0.38.0`](https://github.com/iulita-ai/iulita/releases/tag/v0.38.0) добавил
независимые интеграции: бот Socket Mode и личный read/search доступ владельца.
Публикации ограничены allowlist каналов, approval/auto policy, тихими часами,
часовым лимитом и фильтром секретов. Личный OAuth отклоняет write scopes.
Найденный текст не может сам разрешить автономную публикацию. Audit показывает
метаданные без поискового текста и содержимого сообщений.
