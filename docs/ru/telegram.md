# Telegram: темы, карточки и личные действия

Руководство описывает интеграцию Telegram Bot API 10.4 в текущем исходном коде. Изменения имеют статус **unreleased**, пока не включены в опубликованный бинарник или образ: старый экземпляр потребуется обновить. Настройки Iulita и доступность функций на стороне Telegram — разные условия.

## Начало работы

1. Создайте бота через [BotFather](https://t.me/BotFather), задайте токен через поддерживаемое хранилище секретов и ограничьте `telegram.allowed_ids`, если это личный бот.
2. Для отдельных разговоров включите темы у бота в BotFather. Iulita проверяет объявленную Telegram возможность, но сама не меняет настройки BotFather.
3. Запустите Iulita и откройте личный чат: `/topic` покажет известные темы, `/day` — личный обзор, `/weather London 4` — прогноз.
4. Подключите свои интеграции [Todoist](skills.md#todoist), [Google Workspace](skills.md#google-workspace) или [Craft](skills.md#craft) для соответствующих разделов дня. Неподключённый или недоступный источник имеет явный статус и не выдаётся за успешно загруженный пустой список.

## Команды

| Команда | Действие |
| --- | --- |
| `/topic` или `/topic list` | Известные этому экземпляру Iulita темы текущего владельца. |
| `/topic list 2` | Вторая страница известных тем, по 20 на страницу. |
| `/topic new Заметки проекта` | Предпросмотр и подтверждение создания именованной темы. Без названия бот его запросит; `/cancel` отменяет запрос. |
| `/topic rename Новое название` | Переименование текущей темы с подтверждением. |
| `/topic link` | Ссылка на текущую принадлежащую владельцу тему. |
| `/topic pause` | Приостановка обработки и доставки Iulita в теме. |
| `/topic resume` | Возобновление темы; из общего чата — `/topic resume THREAD_ID`. |
| `/topic delete` | Подтверждение удаления темы и привязанного локального контекста/работы. |
| `/topic bind` | Подтверждение бота для известной старой темы; из общего чата — `/topic bind THREAD_ID`. |
| `/topic recover OPERATION_ID` | Восстановление прерванного создания изнутри созданной темы по выданному Iulita идентификатору операции. |
| `/topic help` | Справка по темам. |
| `/clear` | Очистка контекста только текущего разговора. |
| `/compact` | Явное сжатие текущей личной темы с сообщением нового размера. |
| `/day` | Личная карточка дня. |
| `/day text` | Текстовая версия с кнопками, в том числе для клиента без виджетов. |
| `/status` | Факты и активные инсайты всего аккаунта; сохранённые сообщения и ожидающие напоминания этой беседы. |
| `/weather Иркутск 4` | Текущая погода при наличии данных и прогноз на четыре дня. |
| `/weather text Иркутск 4` | Полный человекочитаемый текстовый прогноз. |
| `/weather` | Четыре дня для места из этой темы или города из памяти; иначе явно обозначенный город по умолчанию — Иркутск. |
| `/weather 7` или `/weather text 7` | Семь дней для выбранного места, карточками или текстом. |

Совместимые команды `/topic close` и `/topic reopen` означают локальные pause/resume. Они не закрывают и не открывают нативную личную тему Telegram. Название темы — одна строка длиной 1–128 символов; обнаруженные секреты и платёжные реквизиты в названии запрещены.

## Контекст темы

При включённых темах обычное сообщение в общем личном чате начинает новую тему. Команды обрабатываются как команды; `/topic` выводит список. Сообщения одного альбома остаются вместе; исходное сообщение копируется в созданную тему как видимое начало разговора.

История и ожидающие взаимодействия разделены по темам. Для проверенной личной темы загружается вся сохранённая история, без незаметного отбрасывания сообщений старше последних 50. При приближении к пределу модели старый контекст заменяется резюме с сохранением ограниченного свежего хвоста. Это сжатие, а не обещание навсегда передавать модели каждое исходное слово.

Автоматическое сжатие и `/compact` оставляют явное уведомление после сохранения результата: оценка токенов до/после, число сообщений и контекстное окно модели. Оценка не равна биллинговому счётчику провайдера. `/clear` очищает текущий контекст и пытается удалить недавние ответы бота в пределах Telegram; тема, другие разговоры, сохранённые факты, напоминания и внешние задачи при этом не удаляются.

### Пауза и удаление

Пауза оставляет тему Telegram открытой, блокируя новые обработки, доставки и действия карточек. Уже отправленный внешний запрос она не отзывает. Пропущенные или подавленные напоминания после возобновления автоматически не повторяются: перенесите их явно.

Подтверждённое удаление сначала фиксирует локальную отметку и очистку: история, резюме и производный контекст темы удаляются, локальные карточки истекают, связанные напоминания и ожидающие/исполняемые задания отменяются, фоновые расписания отключаются. Активные обработки и запросы отменяются; поздние записи и доставки блокируются. Затем удаляется тема в Telegram. При неизвестном результате внешнего вызова локальная очистка остаётся выполненной, а синхронизация ожидается; успех нативного удаления не выдумывается.

**Внешние задачи Todoist, Google и Craft сохраняются.** Другие разговоры и общие сохранённые факты/директивы пользователя не очищаются массово. Уже отправленные внешние вызовы могут завершиться. Удаление темы не является удалением учётной записи.

### Ручное удаление в Telegram

Известные маршруты проверяются периодически, при запуске и при выводе списка тем. Обнаружение не мгновенное и зависит от ответов Telegram. Универсального события удаления и полного API обнаружения всех тем бота нет. Неизвестная ошибка, timeout, ограничение частоты или отказ в доступе не разрешают очистку.

Для разрушительной синхронизации маршрут должен быть привязан к стабильному числовому ID бота. Старая тема без подтверждённой привязки остаётся читаемой, но исключена из автоматической очистки до подтверждения владельцем через `/topic bind`. Переименование или дополнительный username не доказывает принадлежность исторических маршрутов другому боту. Сама привязка сохраняет историю, но включает синхронизацию удаления: если тема Telegram уже удалена, следующая проверка может очистить её контекст и отменить связанную локальную работу. Прочитайте точное подтверждение перед согласием.

## Мой день

Личная карточка содержит разделы задач, напоминаний, событий и фоновых результатов, обновление, страницы и подробности. Обновление читает подключённые источники; автоматические live-уведомления провайдеров не обещаются. Карточка действует 24 часа, затем откройте новую через `/day`. Используется часовой пояс профиля, при его отсутствии для обзора дня — UTC.

| Источник | Возможности |
| --- | --- |
| Todoist | Чтение, подтверждённое завершение и поддерживаемый перенос. Перенос повторяющихся задач отключён. |
| Google Tasks | Чтение подключённых аккаунтов/списков, подтверждённое завершение и перенос даты. |
| Craft | Чтение, подтверждённое завершение и изменение запланированной даты; отдельный deadline сохраняется. |
| Google Calendar | Чтение подробностей событий; карточка не редактирует календарь. |
| Локальные напоминания | Записи текущего разговора, разрешение и перенос подходящих состояний доставки. |
| Фоновые задания | Реальное сохранённое состояние запуска, подробности и доступные файлы результата. |

Скачивание результата создаёт ограниченный и очищенный от распознанных секретов `job-result.txt` из сохранённого результата успешного запуска. Это не ссылка на произвольные созданные артефакты.

Изменение требует точного подтверждения владельца с источником, записью и целевым действием. Для времени доступны завтра в 09:00 или текущий срок плюс день; иной вариант вводится в RFC3339 с явным смещением, например `2026-12-01T18:30:00+03:00`. Прошедшее время отклоняется. Google Tasks и Craft сохраняют только дату, и интерфейс явно сообщает об отбрасывании времени; Todoist может сохранить выбранное время. У Craft выполняются проверки до/после записи без обещания атомарного compare-and-swap.

При **неизвестном результате** доставки или изменения не повторяйте действие. Iulita по возможности проверяет закреплённый источник и показывает неопределённые операции в фоновых результатах. Наличие желаемого состояния само по себе не доказывает причинность. Явное принятие неопределённости разрешает новое намерение, но не превращает старую операцию в успешную и не повторяет старую запись автоматически.

В группе `/day` показывает общую кнопку личного ответа. Ответ получает только нажавший пользователь; для действий откройте личный чат бота и `/day text`. Обычные групповые сообщения не получают скрытый доступ к личной памяти и инструментам.

## Статус памяти

`/status` разделяет два уровня. **Память аккаунта** — все ваши сохранённые факты и активные инсайты с неистёкшим сроком в подключённых Telegram/web-беседах (изолированная память нативного мобильного приложения не входит); числа одинаковы в основном чате и темах. **Этот чат / Эта тема** — сохранённые сообщения и ожидающие напоминания только текущей беседы. Число сохранённых сообщений не является размером контекста модели; сжатие может его уменьшать. При ошибке чтения показано **недоступно**, а не ноль. Личные счётчики доступны только по вашему подтверждённому приватному маршруту; общие фоновые задания в них не входят.

## Погода

Без явно указанного города `/weather` сначала проверяет ваши недавние прямые сообщения именно в этой беседе, затем город из памяти аккаунта. Поддерживаются отдельные утверждения на русском/английском: `Я сейчас в Москве`, `I am in Paris`, `Я живу в Берлине`, `Мой город: Москва`, а также сообщения с геопозицией/местом. Среди текста и геопозиций выбирается самое новое подходящее сообщение. Проверяются последние 30 сохранённых сообщений, среди них — не более пяти ваших реплик за 24 часа; вся история темы не просматривается. Новое распознанное отрицание (`Я уже не в Москве`, `I am no longer in Paris`) или неоднозначное место блокирует прежние сведения из темы и памяти: ответ явно использует город приложения по умолчанию.

Если подходящего утверждения в недавней теме нет, команда проверяет до 200 последних связанных с местом фактов из ваших собственных сохранённых утверждений. Временное «сейчас нахожусь» учитывается до 24 часов; сохранённый город проживания не означает, что вы сейчас там. Цитаты, рассказы о других людях, новые пересланные сообщения Telegram, документы, ответы ассистента и сводки сжатого контекста не устанавливают местоположение. После сжатия учитываются оставшиеся исходные реплики и сохранённые факты; `/clear` удаляет кандидатов из контекста темы, сохраняя память аккаунта. Для произвольной формулировки может понадобиться `/weather ГОРОД`. В старой истории без признака пересылки нельзя надёжно отличить чужое утверждение от вашего.

В тексте и подписи карточки виден источник: сообщение этой беседы, присланное место, сохранённые сведения или Иркутск по умолчанию. Город в `/weather ГОРОД` всегда приоритетнее, уточнение страны сохраняется. Существующему провайдеру погоды передаётся только короткое название места или пара десятичных координат, а не сообщения и факты целиком. Чувствительный или некорректный ввод отклоняется. Ошибка памяти/провайдера не переключает город молча, IP сервера не используется. Подпись присланного места не означает отслеживание текущего GPS.

Работают обычные фразы и `/weather`. Прямая команда принимает 1–16 дней, по умолчанию четыре, и учитывает включение навыка погоды. Все реально полученные дни сохраняются в карточках максимум по четыре строки. Короткий горизонт резервного провайдера обозначается явно.

Показаны место, текущие модельные данные Open-Meteo при их наличии, прогнозные минимумы/максимумы, доступные показатели, источник и время получения. Резервные источники дают только прогноз. Отсутствующее значение не превращается в ноль, а известный ноль сохраняется. Максимум дня не выдаётся за текущую температуру; неизвестные условия не становятся солнцем. Почасовые данные не выдумываются. Текущая погода — данные модели провайдера, а не заявление об измерении локальным датчиком.

Солнце, облака, осадки, туман и ночь нарисованы встроенными иллюстрациями без внешних запросов изображений и шрифтов. Ответ модели сохраняется рядом с карточкой со штатным форматированием. `/weather text ГОРОД ДНИ` выдаёт полный текст без служебных инструкций для модели. Для присланной геопозиции карточка использует описательное место вместо раскрытия координат.

## Возможности Telegram и доступность

Новый интерфейс карточек дня, погоды и общего результата поддерживает английский и русский, для остальных языков используется английский. Это уже, чем интерфейс приложения на шести языках.

Интеграция использует типизированный `go-telegram/bot` с поддержкой Bot API 10.4. Это конкретные возможности проекта, а не обещание включить каждую новую функцию API:

| Возможность | Реализация Iulita |
| --- | --- |
| Личные виджеты и запросы из них | День/погода, действия владельца и личные ответы. |
| Обновление отправленного виджета | Обновление состояния карточки дня с авторизацией, сохранением доставки и восстановлением. Исходный HTML неизменяем. |
| Дополнительные username | Проверка активных имён, адресованных команд и предпочтительного имени ссылок. |
| RichMessage и цитаты | Ограниченное чтение типизированного содержимого; заголовки, списки, таблицы, код и ссылки. Нативная выделенная цитата требует проверки исходной позиции в том же чате/теме; обычный HTML остаётся fallback. |
| Персональный ответ на callback | Личный предпросмотр/подтверждение нажавшему пользователю без публикации личных данных в группе. |
| Inline/shared-виджеты | Реализованы для изолированного тестового сервера Telegram, отключены в production. |
| Платёжные/wallet-поля запросов | Не реализуют кошелёк, переводы или оплату. Неподдерживаемый тип запроса не даёт полномочий. |

Согласно [таблице доступности Telegram](https://core.telegram.org/bots/widgets#availability), в production виджеты сейчас работают только в личном чате бота. Группы, пересылки и inline требуют тестового сервера. [Профиль виджетов](https://core.telegram.org/bots/widgets#what-widgets-support) работает без сети внутри Telegram, а не в WebView Mini App. Клиент без поддержки может показать неподдерживаемое медиа с подписью; бот не способен надёжно определить каждый такой случай.

### Публичные снимки на тестовом сервере

Нужны **отдельные бот и аккаунт тестового сервера**, а также `telegram.test_environment = true`; флаг не разблокирует inline у production-бота. Для этого тестового бота включите inline-режим командой BotFather `/setinline` и задайте подсказку запроса, как описано в [инструкции Telegram](https://core.telegram.org/bots/inline). Затем в чате тестового сервера введите `@YourTestBot calc 12 * 3` или `@YourTestBot time 2026-12-01T12:00:00+03:00 Europe/Berlin`, заменив `YourTestBot` его проверенным именем. Результаты калькулятора и преобразования времени детерминированы. Ответьте на результат `/publish`, проверьте и подтвердите ограниченный очищенный публичный снимок, затем используйте выданный inline-запрос `share SNAPSHOT_ID`. Такой же подтверждённый экспорт может предложить карточка результата задания. Снимки истекают через семь дней. `/unpublish SNAPSHOT_ID` требует подтверждения отзыва; уже сохранённые копии могут остаться. Shared-события разрешают снимок, а не личный разговор владельца.

В production inline-ответы отключены. Обходить эту проверку для включения экспорта не следует.

## Настройки и обновление

```toml
[telegram]
allowed_ids = [] # Для личного бота ограничьте список своими числовыми Telegram ID.
day_widgets = true
day_actions = true
# Необязательно: имена уже назначены ЭТОМУ боту через BotFather.
# aliases = ["ExampleAssistantBot"]
# preferred_username = "ExampleAssistantBot"
test_environment = false
```

Пустой список разрешает всех пользователей. Токен задаётся через поддерживаемое хранилище секретов, не публичный пример. `day_widgets` и `day_actions` включены по умолчанию, в том числе после обновления старой конфигурации без этих ключей. Явное false сохраняется. Сохранённые настройки дашборда имеют приоритет над значениями по умолчанию. После изменения этих переключателей нужен перезапуск.

- `day_widgets = false` отключает и `/day`, и `/day text`, а также иллюстрированные карточки погоды. `/weather` продолжает выдавать полный текст прогноза; `/weather text` тоже доступна при включённом навыке погоды.
- `day_actions = false` делает карточку дня только читаемой. Другие навыки и их подтверждения этим не отключаются.
- Переменные окружения: `IULITA_TELEGRAM_DAY_WIDGETS` и `IULITA_TELEGRAM_DAY_ACTIONS`.
- `aliases` не назначает и не покупает username. Все активные имена обнаруживаются при запуске по числовой личности бота, даже без `aliases`. Команды вида `/day@OldActiveName` продолжают работать, пока имя активно; `preferred_username` выбирает имя ссылок. При ошибке проверки сохраняется канонический fallback без доверия чужой личности.
- У нескольких экземпляров Telegram могут различаться token, allowlist, debounce/rate, имена и тестовая среда. Переключатели карточек/действий глобальны и применяются ко всем экземплярам; это не поля JSON отдельного instance.

Полный список см. в [конфигурации](configuration.md#telegram).

## Эксплуатация

Чтобы проверить личность бота без изменений, предоставьте токен через именованную переменную окружения и выполните из исходников:

```bash
go run ./cmd/telegram-readiness
# Только отдельные токены тестового сервера:
go run ./cmd/telegram-readiness -token-env TELEGRAM_TEST_TOKEN -test-environment
```

Команда выводит публичный ID, активные username, флаги тем и доступность проверки имён. Она не читает очередь updates, не отправляет сообщения, не меняет BotFather и не печатает токен. Это не доказательство отрисовки, права изменения задач или доставки.

Если темы недоступны, проверьте BotFather и объявленный флаг возможности. `/topic` перечисляет известные сохранённые темы, а не всё, что когда-либо показывал клиент. При **Widget stopped** откройте новую карточку и попробуйте `/day text` либо `/weather text ГОРОД ДНИ`; при обращении за помощью укажите версию клиента. Нельзя заменить HTML уже отправленного виджета обновлением state. При подходящей ошибке API Iulita переходит к тексту, но не обнаруживает все ошибки клиентской отрисовки.

### Приватность

Ответ Telegram буферизуется до итоговой проверки, чтобы непроверенные фрагменты не успевали появиться в чате. Подозрительные ключи и платёжные реквизиты отправляются только адресату через ephemeral API, без кнопок сохранения/копирования. При отказе выдаётся нейтральное сообщение, а не обычная отправка секретного текста. Подтверждения и callback сохраняют исходного пользователя и тему.

Обнаруженные payment entities, номера карт/TON и секреты очищаются до передачи модели, истории и закладкам в поддерживаемых путях. Это best-effort обработка текста и entities, а не гарантия для OCR, бинарных вложений и обфускации. HTML модели не исполняется в виджете. Подробности — в [разделе безопасности](security.md#безопасность-telegram).
